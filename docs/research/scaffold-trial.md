import { paraglideMiddleware } from '#lib/paraglide/server.js';

const handleParaglide: Handle = ({ event, resolve }) =>
	paraglideMiddleware(event.request, ({ request, locale }) => {
		return resolve(
			{ ...event, request },

Answers:

- **Strategy option that works:** `strategy: ['baseLocale']` on `paraglideVitePlugin` in `vite.config.ts`. Generated `runtime.js` then has `export const strategy = ["baseLocale"];`. Valid strategy names per `runtime.js:40`: `cookie`, `baseLocale`, `globalVariable`, `url`, `preferredLanguage`, `localStorage`, `custom-*`.
- **`hooks.server.ts`:** not needed for the build or for message rendering. Its only observable effect in a prerendered single-locale build is filling `%paraglide.lang%` / `%paraglide.dir%`. Can be deleted **if** `app.html` gets a literal `lang` (v3b); deleting it without editing `app.html` ships the raw placeholders (v3a).
- **`hooks.ts` reroute:** not needed; can be deleted. No URL strategy is active, so there is nothing to de-localize. Build and all routes work without it (v3a, v3b).
- **Cookie:** with `['baseLocale']`, `grep -c "document.cookie" build/_app/immutable/chunks/*.js` returns no non-zero match. The string `PARAGLIDE_LOCALE` still appears in one chunk as an unused constant.
- The hidden locale-links block in `+layout.svelte` was left in place in the trial; it builds and lints. It still imports `runtime.js`.
- Not tested: behaviour in `npm run dev` / `npm run preview` in a browser, client-side navigation. **UNVERIFIED**.
